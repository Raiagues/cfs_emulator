# Design pack questions

| Where the references differ | Implementation interpretation |
| --- | --- |
| `03` shows jobs starting on arrival at Boot. `02`, audit F1 and the owner require pure routes. The Boot prototype reaches Operational on a clock. | A verified, idle Boot screen offers **Start first boot** (F1). Continue, Back, Forward and direct links only navigate. Job events drive milestones and the recorded replay drives replay timing. |
| `01`, `04` and the previews highlight multiple open choices. The owner requires exactly one coach. | Guide one available choice at a time. Keep all alternatives operable and unselected. During passive animation wait for its next action. |
| The preview Event flow starts with a selected command. The App preview can advance without typing. `03`, `06` and the owner require each first action to be performed. | Keep the sequences and motion. Require Connect, selection, typed values and explicit Send/Create. Count actual cFS observations. |
| Some preview links target `*.dc.html` filenames absent from the preview directory. The shipped Main runner leaves the preview after Continue. | Use the destinations in `03` in the product. Standalone preview navigation is reference evidence only. |
| `05` includes superseded declarations for the hand, coach and shake. The placement table, wording and owner require the final coach and an active wrong-answer shake. | Use `fsCoach2` at 1.8 s, omit the hand, alternate the two 0.5 s shake animations. Honour the specified reduced-motion rules. |
| `10` lists streaming batch checks as unused. `02` and `03` require the NDJSON batch. | Use the stream for the explicit target action. Retire the duplicate batch protocol. |
| The detailed UX report suggests a confirm for reset, a combined rebuild/restart, an emulator-only fallback and alternate labels. `03` specifies server reset without a dialog, individual build/run buttons and all three sensor targets. | Follow `03` and the native register transport in `08`. |
| `02` specifies per-target steps. `03` requires the optional Board visit to retain the first eight steps on the originating target. | Keep the originating target's journey visible in Board setup. Attach Board completion to an OPERATIONAL observation of the verified physical deployment. |
| The physical sensor path in `03` and `08` reads real devices while the common evidence description calls for a synthetic write. | Confirm a real reading from the linked device in the physical app's telemetry. Native needs a register write and the matching telemetry, and QEMU needs a confirmed QMP write. |
| The full inventory includes free editor, bench and terminal controls. The global table in `03` names their entry points and leaves their internal controls unspecified. | Keep the inventory of these controls. Compare first-run controls and the listed global destinations with `03`; test free-view links against their live handlers. |
